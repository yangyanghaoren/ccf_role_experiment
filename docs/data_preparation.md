# 400 案角色实验：数据处理方法与复现记录

## 已核实的数据链

| 阶段 | 可追溯来源 | 本次核实范围 |
| --- | --- | --- |
| 500 条待去重材料 | `data/source/ccf_500_candidates.json` | 500 条 P/D/F/R 均非空 |
| 400 条保留材料 | 新脚本的去重输出与既有 `ccf_400_full_source.json` | 保留 original_id 及 P/D/F/R 与既有数据完全一致 |
| 400 条 gold | 既有 `ccf_400_full_source.json`、`ccf_400_verified_gold.json` | 复用已有标签并核验关联，不重新判断裁判结论 |
| S1–S6 | 正式构造脚本输出与既有六组材料 | 400 案逐条 JSON 内容完全一致 |

论文中的 643→500 阶段包含完整性和任务适用性的人工审核，以及法律规则 R 的整理。候选池脚本仅完成规则筛选和 P/D/F 提取；仓库复用冻结的 500 案材料，不将历史随机删样脚本视为人工审核的实现。第二轮人工标注和中性化语义核验需要真实审核记录支持，程序不会代替或宣称执行这些步骤。


## 本次明确实现的去重规则

1. 输入必须是非空 JSON 数组；id 为唯一正整数，P/D/F/R 为非空字符串，Category 为对象。缺失关键字段时直接报错，不默默排除样本。
2. 按 P、D、F、R 的固定顺序拼接，不插入分隔符。
3. 对拼接文本实施 Unicode NFKC 规范化。
4. 使用正则 `\d+` 将每段连续数字替换为 `<NUM>`。日期中的分隔符、金额中的小数点等标点保留；例如 `１２３.４５` 变成 `<NUM>.<NUM>`。
5. 使用 `\s+` 删除空白，包括空格、换行和制表符。
6. 在全部 500 条规范化文本上拟合字符级 TF-IDF：n-gram 范围 3–5，lowercase=True，smooth_idf=True，use_idf=True，sublinear_tf=False，min_df=1，max_df=1.0，norm=l2，float64。向量器的小写转换也会将占位符变为 `<num>`。
7. 计算文书对之间的余弦相似度，相似度 **≥0.75** 时建立无向边，不对相似度先做四舍五入。
8. 用相似度图的连通分量形成候选重复簇。若 A–B 和 B–C 达到阈值，即便 A–C 未达到阈值，三者也在同一簇内。因此该定义并不要求簇内所有文书两两达到阈值。
9. 每簇保留原始 id 最小的文书，剔除其余文书。孤立文书全部保留；最终输出按输入中的先后顺序排列。当前 500 案原始编号与顺序一致。
10. 样本集合确定后，关联既有 gold 和来源信息，统一重新编号为 1–400，并保存 original_id。规范化文本只用于去重，不替换模型接收的原始文本。

本次实现得到 38 个多文书重复簇、361 条达到阈值的文书对、100 份剔除文书和 400 份保留文书。保留编号与原有正式数据完全一致；既有来源数据的 CaseId 也有 400 个不同值。

“数字统一替换”并不足以唯一确定算法。本次试算中，将连续数字替换为单个 `0` 会得到 37 个簇、401 份保留文书；替换为 `<NUM>` 得到上述 400 份结果。逐个数字替换为 `0` 也能得到相同保留集合。因此，匹配历史结果并不能证明找回了唯一的历史实现。本项目明确保存本次使用的 `<NUM>` 实现及依赖版本，阈值始终保持 0.75，没有按目标数量强行删样。

## 样本冻结与条件构造

去重独立于 gold 进行，既有 400 案编号不参与相似度计算或重复簇代表选择，只在去重后用于一致性检查。

`data/source/ccf_400_role_texts.json` 保存每案中性化后的 P/D/F 及 S3 字段置换。该文件由既有 S2/S3 恢复得到：S2 是中性 P、D、F 和 R 按双换行拼接；S3 使用同样三个中性段落，在 P/D/F 角色间进行完全错配。原有样本使用两种完全错配置换，分别为 187 案和 213 案，脚本保留其逐案映射，不重新随机分配。每条记录关联原始材料 SHA-256，防止改动材料后误用旧角色文本。

生成规则：

| 条件 | 材料 |
| --- | --- |
| S1 | 冻结中性 P、D、F，加同一 R；调用程序添加正确角色标题 |
| S2 | 已有中性 P、D、F，加同一 R，以双换行拼接；调用程序使用“案件材料”标题 |
| S3 | 将已有中性 P/D/F 按冻结映射填入错配角色字段，加同一 R；调用程序添加角色标题 |
| S4 | 交换中性 P/D，F/R 不变 |
| S5 | 交换中性 P/F，D/R 不变 |
| S6 | 交换中性 D/F，P/R 不变 |

S1–S6 共用同一组中性段落。S2 是 S1 的 P/D/F/R 顺序拼接；S3 改变段落与角色的对应关系，并保留历史逐案循环置换；S4–S6 进行固定两两交换。逆向还原后，各角色文本与 S1 精确一致，R 不变。中性化仅减少显式来源标记，不保证消除全部语义或风格线索；是否保持原有事实含义仍需真实的语义核验记录支持。

脚本核验全部保留样本与既有来源和角色标注的编号集合、材料内容及哈希，再保存冻结来源及六组条件。生成后逐案核验编号、Category、R、精确文本映射及答案隔离，并将检查定义记录到 manifest。gold 单独导出，保留原始来源文本，不加入六组模型输入；代码不会根据文本猜测 gold，也不会宣称执行了人工核验。

## 可用于论文的去重方法表述

> 对500份待实验文书进行近重复检测。首先，按原告诉称（P）、被告抗辩（D）、法院认定事实（F）和法律规则（R）的顺序拼接文本，进行Unicode NFKC规范化，将连续数字序列统一替换为占位符，并去除空白字符。随后，在全部样本上构建字符级TF-IDF表示，采用3—5 gram特征并计算文书间的余弦相似度。对相似度不低于0.75的文书对建立连接，以相似度图的连通分量形成候选重复簇，每簇保留原始编号最小的文书。该流程识别出38个重复簇，剔除100份近重复文书，最终保留400份文书。去重完成后固定样本集合及既有标准答案，使用同一套中性化文本构造S1–S6六种实验条件，保证各条件的案件集合、样本编号、法律规则和标准答案一致。

实现细节或附录中应写明占位符为 `<NUM>`，以及上面的 TF-IDF 参数。“近重复文书”是算法筛选结果；仅凭文本相似度和不同 CaseId，不能严格证明所有样本在法律案件层面相互独立。因此主文更适合写“400份去重后的文书”或“400份研究样本”。

## 验证与输出

完整数据回归使用 500 案输入进行去重，逐条比较 S1–S6、gold 和冻结来源文件，八个文件的 JSON 内容均一致。7 项自动测试覆盖规范化、不改动原文、阈值边界、传递聚类、最小编号保留、缺失字段、编号重复、标注哈希、gold 隔离、数量不符时停止，以及完整数据回归；对交换文本、R、S2 拼接、S3 循环映射、案件集合或答案隔离的破坏均应报错。

历史审计文件位于 `data/processed/role_experiment/`，可能保留旧版三条件 manifest，不应当作更新后六条件输出。请使用新的空输出目录运行 `build` 命令。`dedup_report.json` 记录实测数量、完整参数、输入哈希和依赖版本，`duplicate_clusters.json` 与 `similarity_edges.json` 可逐簇核查。程序拒绝覆盖非空目录，不调用模型。
